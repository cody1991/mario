# Feature Specification: 超级马里奥 Web 版 V1

**Feature Branch**: `001-mario-game-v1`  
**Created**: 2025-12-12  
**Status**: Draft  
**Input**: User description: "第一版本的超级马里奥，可以实现基本的游戏玩法就好"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 基础移动与跳跃 (Priority: P1)

玩家打开游戏后，可以使用键盘控制马里奥角色在游戏场景中左右移动和跳跃。这是游戏最核心的交互方式，没有移动和跳跃就无法进行任何游戏体验。

**Why this priority**: 移动和跳跃是平台游戏的基础，所有其他玩法都依赖于此。

**Independent Test**: 玩家可以在空白场景中自由移动马里奥，验证左右移动流畅、跳跃高度合理、落地自然。

**Acceptance Scenarios**:

1. **Given** 游戏已加载完成, **When** 玩家按下左/右方向键, **Then** 马里奥向对应方向移动
2. **Given** 马里奥站在地面上, **When** 玩家按下跳跃键, **Then** 马里奥跳起并在重力作用下落回地面
3. **Given** 马里奥在空中, **When** 玩家按下方向键, **Then** 马里奥可以在空中调整水平方向
4. **Given** 马里奥在移动中, **When** 玩家松开方向键, **Then** 马里奥逐渐减速停止（有惯性）

---

### User Story 2 - 关卡场景与平台 (Priority: P2)

玩家可以在包含地面、平台、砖块的关卡场景中游玩。场景提供了游戏的空间结构，让玩家有目标可以探索和挑战。

**Why this priority**: 有了移动能力后，需要有场景来承载游戏内容，平台和障碍物让游戏有挑战性。

**Independent Test**: 玩家可以在一个包含多层平台的关卡中跳跃穿行，验证碰撞检测正确、平台可站立。

**Acceptance Scenarios**:

1. **Given** 关卡已加载, **When** 马里奥移动到平台下方并跳跃, **Then** 马里奥可以站在平台上
2. **Given** 马里奥站在平台边缘, **When** 马里奥继续向前移动, **Then** 马里奥从平台边缘掉落
3. **Given** 马里奥接触砖块侧面, **When** 马里奥继续移动, **Then** 马里奥被砖块阻挡无法穿过
4. **Given** 关卡宽度超出屏幕, **When** 马里奥向右移动, **Then** 画面跟随马里奥滚动

---

### User Story 3 - 敌人与碰撞 (Priority: P3)

关卡中存在敌人（如栗子怪 Goomba），玩家需要躲避或踩踏消灭敌人。敌人增加了游戏的挑战性和趣味性。

**Why this priority**: 敌人是游戏挑战的核心来源，但需要先有稳定的移动和场景系统。

**Independent Test**: 玩家可以在有敌人的场景中游玩，验证敌人移动正常、碰撞判定准确。

**Acceptance Scenarios**:

1. **Given** 关卡中有敌人, **When** 敌人自动移动, **Then** 敌人沿地面左右巡逻
2. **Given** 马里奥从上方落到敌人头上, **When** 碰撞发生, **Then** 敌人被消灭，马里奥弹跳
3. **Given** 马里奥从侧面接触敌人, **When** 碰撞发生, **Then** 马里奥受伤或死亡
4. **Given** 敌人移动到平台边缘, **When** 敌人继续移动, **Then** 敌人掉落或转向

---

### User Story 4 - 金币收集 (Priority: P4)

关卡中散布着金币，玩家可以收集金币获得分数。金币提供了探索的奖励和成就感。

**Why this priority**: 金币是经典马里奥的核心元素，但不影响基础游戏流程。

**Independent Test**: 玩家可以在关卡中收集金币，验证金币消失、分数增加。

**Acceptance Scenarios**:

1. **Given** 关卡中有金币, **When** 马里奥接触金币, **Then** 金币消失并播放音效
2. **Given** 马里奥收集金币, **When** 金币消失, **Then** 分数增加相应数值
3. **Given** 屏幕上有分数显示, **When** 马里奥收集金币, **Then** 分数实时更新

---

### User Story 5 - 游戏状态管理 (Priority: P5)

游戏具有开始、进行中、胜利、失败等状态，玩家可以开始游戏、重新开始。

**Why this priority**: 完整的游戏循环需要状态管理，但可以在核心玩法完成后添加。

**Independent Test**: 玩家可以从开始界面进入游戏，死亡后可以重新开始。

**Acceptance Scenarios**:

1. **Given** 游戏首次加载, **When** 加载完成, **Then** 显示开始界面或直接进入游戏
2. **Given** 马里奥死亡, **When** 死亡动画播放完毕, **Then** 显示重新开始选项
3. **Given** 马里奥到达关卡终点, **When** 触碰旗杆, **Then** 显示胜利画面

---

### Edge Cases

- 马里奥移动到屏幕左边界时，画面不再向左滚动（左边界锁定）
- 马里奥掉落到屏幕下方时，判定为死亡
- 多个敌人同时接触马里奥时，只触发一次伤害判定
- 马里奥在跳跃过程中碰到天花板时，立即开始下落
- 游戏窗口失去焦点时，游戏暂停

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 游戏 MUST 支持键盘控制马里奥移动（左右方向键或 A/D 键）
- **FR-002**: 游戏 MUST 支持键盘控制马里奥跳跃（空格键或上方向键）
- **FR-003**: 马里奥 MUST 受重力影响，跳跃后自然下落
- **FR-004**: 游戏 MUST 实现马里奥与地面、平台、砖块的碰撞检测
- **FR-005**: 游戏 MUST 实现画面跟随马里奥水平滚动
- **FR-006**: 游戏 MUST 包含至少一个可游玩的完整关卡
- **FR-007**: 关卡 MUST 包含敌人（至少一种类型）
- **FR-008**: 游戏 MUST 实现马里奥与敌人的碰撞判定（踩踏消灭/侧面受伤）
- **FR-009**: 游戏 MUST 包含可收集的金币
- **FR-010**: 游戏 MUST 显示当前分数
- **FR-011**: 游戏 MUST 有明确的胜利条件（到达终点）和失败条件（死亡）
- **FR-012**: 游戏 MUST 支持重新开始

### Key Entities

- **Mario（马里奥）**: 玩家控制的主角，具有位置、速度、状态（站立/跳跃/死亡）属性
- **Level（关卡）**: 游戏场景，包含地形数据、敌人位置、金币位置、起点和终点
- **Platform（平台/砖块）**: 可站立的地形元素，具有位置和尺寸
- **Enemy（敌人）**: 会伤害玩家的 NPC，具有位置、移动方向、存活状态
- **Coin（金币）**: 可收集的道具，具有位置和收集状态
- **GameState（游戏状态）**: 管理分数、生命、游戏进程

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 玩家可以在 3 秒内完成游戏加载并开始操作
- **SC-002**: 游戏画面保持流畅，无明显卡顿（目标 60 帧/秒）
- **SC-003**: 玩家操作响应延迟不超过 100 毫秒
- **SC-004**: 碰撞检测准确率达到 100%（无穿墙、无悬空站立）
- **SC-005**: 新玩家可以在 1 分钟内理解基本操作并开始游戏
- **SC-006**: 关卡可在 2-5 分钟内通关（适中难度）
- **SC-007**: 游戏支持主流浏览器（Chrome、Firefox、Safari、Edge）

## Assumptions

- 游戏面向桌面浏览器，键盘为主要输入方式（移动端触控为后续版本）
- 使用经典 NES 风格的像素美术风格
- 音效和背景音乐为可选功能，不影响核心玩法
- 关卡数据可以硬编码，不需要关卡编辑器
- 不需要用户账号系统或在线功能
- 图片素材可从网络获取开源/免费资源
